# 公开注册准备（未上线）

本补丁补齐邮箱验证码输入、重发、未验证账号恢复入口和本机数据提示；不改变认证配置、Worker 白名单、存储归属或同步行为。

## 上线阻碍

- 自有邮件服务及发信域名尚未准备；仍使用 Shared，不宜正式公开注册。
- 当前本地记录按浏览器站点保存，没有按账号隔离；退出和切换账号仍能访问同一批记录。提示文字不能代替隔离，不能宣称支持共用浏览器下的账号隐私。
- Worker ALLOWED_USER_IDS 仍为显式白名单。新注册账号不会自动获得 API 授权；此次保留该限制，不开放同步。
- Neon Auth 默认 production 分支同时供固定预览和生产网页使用。配置切换会同时影响两者，不能将其当作隔离的 Auth 测试环境。

## 准备与验收顺序

1. 在功能分支审查邮箱验证补丁；保持 Draft，不合并 main。
2. 准备自有发信域名及邮件服务，按服务商要求完成域名所有权和发信 DNS 验证；SMTP 凭据由用户直接填在 Neon，不能提交仓库或聊天。
3. 先准备隔离的 Auth 测试分支或安排明确的维护测试窗口；确认后才开启邮箱注册验证，选择数字验证码（OTP）。当前补丁也提示用户如何使用邮件验证链接。
4. 用新测试邮箱确认收码、错误码、过期码、重发和验证后登录；用已有未验证账号确认收到 EMAIL_NOT_VERIFIED 时可进入验证；确认现有账号不会因切换配置被锁定。
5. 完成账号间本地数据归属/隔离设计，保留并备份旧的本地记录，未经用户明确选择不把旧记录绑定或上传至任何账号。
6. 正式上线前关闭生产 Auth 的 Allow Localhost，保留生产及固定预览可信域名。若提供 Google 登录，改用自有 OAuth 凭据并补齐客户端入口；当前只提供邮箱密码登录。
7. 用户已确认 ALLOWED_ORIGINS 包含两个网页来源。Pages Preview 与 Production 各有两个 VITE_ 地址；Worker 生产五个 Secret 名称已确认存在，未读取其敏感值。
8. 所有阻碍解决且收到用户明确确认后，才合并、部署生产并复验。记录旧 Pages 部署和 Worker 版本；回滚时恢复已验证版本，不删账号或本地记录。

关闭生产 localhost、启用验证、替换邮件服务均需在补丁审查及测试方案确认之后进行。本补丁不宣称已完成真实邮件或浏览器端到端验收。
