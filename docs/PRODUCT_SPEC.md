# 日序 Rixu 产品规格与设计约定

本文件保存长期产品要求，不代表所有功能已经完成。实际实现、验收与发布状态见 [PROJECT_STATUS.md](PROJECT_STATUS.md)，开发约束见仓库根目录 [AGENTS.md](../AGENTS.md)。新增会话先读这三个文件，再检查代码和 PR；不要仅从旧 README 推断进度。

## 定位与当前使用范围

日序是面向个人长期使用的生活与时间管理应用，整合每日计划、任务、专注、记账、备忘提醒、长期目标、复盘、智能输入与多端同步。理念是简洁、安静、高效、个性化，减少操作步骤。它是已有代码和历史设计的项目，不能另起炉灶重写。

当前以用户个人自用为主，暂缓公开注册、自有邮件服务和发信域名准备。保留认证与同步方向；暂停公开注册准备不等于可以取消身份验证、白名单或数据保护。

统一一个个人空间，不再引入演示空间与个人空间切换。未登录可用主要本地功能；云账号不应成为本地使用的门槛。

## 设备与平台

- 主力手机：华为 Pura 70 Pro+，HarmonyOS 4.2.0，可安装 Android APK，并非 HarmonyOS NEXT。
- 不得默认有 Google Play Services。主要本地功能与计划中的系统提醒不能依赖 Google 服务；第三方登录只能作为可选方式。
- 当前开发平台为 Windows，另有 Apple Silicon Mac 可用于后续构建。
- Vue + TypeScript + Vite 共用前端，移动容器采用 Capacitor。优先适配安卓 WebView、触摸操作、键盘与安全区域。
- 必须考虑后台与锁屏限制、通知权限、电池管理、系统中断恢复；网页前台可用不等于安卓后台可靠。

## 功能规则

### 今日计划与跨天计划

每日任务支持临时新增、预计时长、完成状态、实际完成量、分类、标签、备注、开始及截止时间。不默认把任务锁定在上午、下午等时段。

支持电脑生成完整计划文件，再导入手机，例如六级 33 天计划、运动或养生计划。必须支持跨天批量导入、预览、错误校验和重复导入处理，不要求用户逐条建立任务。

### 专注

点击任务可进入专注并设置本轮时长；支持学习与严格两种模式、暂停、继续、提前结束、有效时长累计、倒计时和柔和背景音。

学习模式允许正常切换应用内界面；严格模式离开专注界面或页面隐藏时须按既有规则暂停或限制。不得把当前暂停规则描述成系统级禁止退出。

当前有效专注时长必须立即进入当天的实际时间分布，不等任务完成或专注结束。按时间戳、有效区间和持久检查点计算，避免依赖前台定时器次数；不得重复累计、算入暂停时间或因恢复中断伪造时长。安卓后台计时、锁屏展示、通知和中断恢复需单独设计验收。

### 备忘与长期目标

备忘是有截止时间的单次事项，例如未来七天需完成的作业；截止当日进入今日任务视图，不能每天生成重复副本。

长期目标用于考试、项目节点、长期坚持事项，要求多目标、倒计时、打卡与进度。备忘与目标应有清楚语义，但入口和展示保持集中、便捷。具体实现覆盖率以代码和验收为准。

### 智能输入与记账

文字与语音自然输入可拆分多笔收支，例如“今天早饭花了八块，中午吃饭花了19.2元，晚上网上购物28.8元”。识别金额（含中文数词）、日期、收支类型和分类，允许修改金额、名称、类别、标签、日期。

暂存草稿只进入待确认收件箱；正式入账仅保存明确选中且有效的候选。无金额、含糊或矛盾内容应保持待确认，不能隐式入账，也不能在记账模式下误存为计划任务。金额采用整数分，不能产生浮点累计误差。

要求日、月、季度、半年、年及自定义区间统计，分类圆环图、月预算与分析建议。语音可用性依赖实际平台支持，不能把文字解析通过当成语音真机验收。

### 复盘

记录每日任务完成量、计划与实际时长、专注时长、分类时间占比；支持日历完成状态颜色、每日复盘文字、分类圆环图、长周期趋势和统计。

统计必须基于真实记录、时区和跨天区间。没有云端 AI 时可提供本地规则分析，必须如实标示，不能冒充 AI 输出。

### 提醒

产品要求覆盖开始前十分钟、开始时、截止、超时未完成等提醒；支持远期与临近规则、重复次数/间隔、自定义时间，单任务稍后提醒、暂停、恢复和彻底停止。

未来手机端应使用系统通知并验收锁屏、权限拒绝、系统回收及重启后的行为。当前前台弹窗不能被描述为已实现后台通知。产品要求与当前默认规则不同的部分应列为待实现，不可仅改文案宣称支持。

### 标签与分类

支持新增、编辑、删除、归类；系统默认分类也应可合理管理。删除或调整分类不能误删账目、任务或破坏引用。

## UI 与交互

延续 V2.2：极简、低饱和、留白；仅少量手绘插画、微图标、柔和色块，不堆装饰边框。现代、细腻但克制。

手机优先，底部导航、弹窗、抽屉、折叠区域便捷；减少重复解释与提示，避免寻找一个功能反复滚动。新功能优先放在现有合理入口，不另造并行导航。

## 数据与云端

本地优先，云端同步。浏览器使用 IndexedDB；未来 SQLite 必须先设计迁移、兼容、失败恢复与外部备份，不能直接替换旧存储或改变数据库名使数据不可见。

首次登录不自动上传、拉取覆盖、删除或绑定已有记录；首次同步必须由用户明确确认账号、范围与合并方式。必须有稳定的用户归属、版本控制、冲突处理、幂等重试、删除同步与失败恢复。界面登录成功、GET /v1/me 成功、后端存在同步表或传输函数，都不代表端到端同步完成。

同一浏览器的不同账号数据归属与隐私隔离需在账户同步前处理。不能未经确认把历史本地数据归给第一个登录账号；退出也不能为“隔离”而清空数据。个人单账号使用可保留本地模式，但须如实说明边界。

Neon 数据库密码与 AI 密钥仅在服务端；VITE_ 变量只允许公开地址。不能把真实备份、账本、Cookie、JWT、密码、SMTP/签名密钥写入源码、日志、聊天或公开构建产物。

## 开发顺序

按用户 2026-11-23 最新交接要求：先完成 V0.3.3 认证可靠性与个人使用范围的上线验收，再做可靠多端同步，随后完善 Android APK 与后台提醒，云端 AI 后续接入。

已有安卓调试首包作为成果保留，不因此宣称真机、长期签名、同步、SQLite 或后台提醒已完成。若用户后续调整优先级，更新本文件和状态记录，不丢失此前决策。
